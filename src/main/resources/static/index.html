Architecture Flow

Client → REST API → PostgreSQL → Outbox → Kafka → Consumers (Inventory, Payment, OrderStatus, Notification) → PostgreSQL → Client

This dashboard demonstrates the backend architecture. The core focus is on reliable event processing, not UI complexity. Use Swagger UI to interact with the APIs, and Actuator endpoints for observability.

Core Patterns

  • Transactional Outbox Pattern
  • Idempotent Consumers
  • Retry + Dead Letter Queue
  • Optimistic & Pessimistic Locking
  • Redis Caching with Fallback
  • JWT + RBAC Security

Endpoints

  • POST /api/auth/register & /login
  • GET /api/products (cached)
  • POST /api/orders (creates event)
  • GET /api/orders/{id}
  • GET /api/inventory/{productId}
  • GET /api/notifications

Event Flow Example

POST /api/orders → Order CREATED → outbox_events PENDING → Kafka order.created →
InventoryConsumer: reserve stock → order INVENTORY_RESERVED → Kafka inventory.reserved →
PaymentConsumer: process payment (5% fail) → order PAYMENT_COMPLETED → Kafka payment.processed →
OrderStatusConsumer: confirm inventory, order COMPLETED → Kafka order.completed →
NotificationConsumer: create notification → User sees COMPLETED

Quick Start

# 1. Start full stack
docker compose up -d

# 2. Register user
curl -X POST http://localhost:8080/api/auth/register \
-H "Content-Type: application/json" \
-d '{"username":"demo","email":"demo@test.com","password":"demo123"}'

# 3. Login
curl -X POST http://localhost:8080/api/auth/login \
-H "Content-Type: application/json" \
-d '{"usernameOrEmail":"demo","password":"demo123"}'

# 4. Browse products (no auth)
curl http://localhost:8080/api/products

# 5. Create order (with JWT)
curl -X POST http://localhost:8080/api/orders \
-H "Authorization: Bearer <token>" \
-H "Content-Type: application/json" \
-d '{"items":[{"productId":1,"quantity":2}]}'

# 6. Check status
curl http://localhost:8080/api/orders/1 \
-H "Authorization: Bearer <token>"
